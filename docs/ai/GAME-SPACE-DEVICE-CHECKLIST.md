# Game Space — قائمة التحقق على جهاز (P5)

> كل ما بُني في P0–P4 **لم يُبنَ ولم يُجرَّب**؛ هذه القائمة هي الطريق من «مكتوب» إلى «مُتحقَّق». نفّذها بالترتيب، وسجّل الناتج
> في `HANDOFF.md` (إدخال جديد) وفي `VALIDATION.md` §12. ما يفشل **يُسجَّل كما هو**، ولا يُعدَّل وصفُه ليبدو نجاحًا.

## ٠) قبل البدء
```sh
cd manager && ./gradlew :app:compileReleaseKotlin && ./gradlew :app:testReleaseUnitTest   # Quick Verify
./gradlew :app:installRelease          # أو الصيغة المعتمدة عندك
adb devices                            # جهاز واحد (أو -s SERIAL)
```
- Shizuku مبدوء **عبر adb** (uid 2000)، لا بالجذر، وإلا لا تمثّل النتائج وضع Shizuku.
- افتح التطبيق مرة واحدة ومنح إذن التراكب (Overlay).

## ١) المسبار الآلي (٥ دقائق) — يجيب عن أكبر مجهول
```sh
bash tools/gamespace_shell_probe.sh -n 5 -o probe-$(date +%F).txt
```
يجرّب بصلاحية الـshell **الأوامر نفسها** التي ترسلها الميزات عبر `PrivilegedShell.exec` (كتابة `settings` في الفضاءات الثلاثة،
`zen_mode`، مفاتيح معدّل التحديث والاهتزاز، `screencap`، `screenrecord` + بقاء الحلقة الخلفية، `wm`، `appops set GET_USAGE_STATS`،
`svc`) ويعيد كل شيء إلى حاله، ويقيس الإقلاع البارد (`-n`).

| السطر في التقرير | إن فشل فمعناه | الإجراء |
|---|---|---|
| `settings put secure/system/global` | uid الـshell لا يملك الكتابة في ذلك الفضاء | `InAppProfileApplier` لن يطبّق معدّل التحديث/الاهتزاز تحت Shizuku؛ يُسجَّل في `KNOWN_ISSUES` وتُعاد المجموعة الجزئية |
| `zen_mode write-back` | عدم الإزعاج لا يُكتب بالـshell | نفسه (DND) |
| `screencap` / `screenrecord` | الميزة لا تعمل تحت Shizuku | يُرفع `GameFeature.SCREENSHOT/SCREEN_RECORD` إلى `ROOT` |
| `screenrecord background loop` | حلقة التسجيل تموت بعد عودة الصدفة | يُستبدل `&` بخدمة طويلة العمر أو يُرفع المطلوب إلى `ROOT` |
| `wm write-back` | `PanelResolution` لا يعمل بالـshell | يُرفع `DISPLAY_SCALE` إلى `ROOT` |
| `appops set GET_USAGE_STATS` | زرّ «امنح» لن ينجح | يبقى البديل اليدوي (صفحة الإعدادات) فقط |
| `svc wifi/data` | مقبضا Wi-Fi/البيانات لا يعملان بالـshell | يُرفعان إلى `ROOT` |

بعد كل فشل: عدّل `GameFeature.requires` **وجدول القسم د** في `GAME-SPACE-PLAN.md` في الدفعة نفسها.

## ٢) وضع Shizuku — على الجهاز نفسه
| # | الخطوة | المتوقَّع |
|---|---|---|
| ٢٫١ | خيارات اللوبي ← «وضع التنفيذ» ← Shizuku | الحال «الفعّال: Shizuku»، والشارة في الكبسولة «Shizuku»، ولا نافذة `su` |
| ٢٫٢ | أعد تشغيل التطبيق وهو في وضع Shizuku | **لا** نافذة صلاحية جذر عند الإقلاع |
| ٢٫٣ | صفّ «كشف اللعبة الأمامية» ← «امنح» | يصير «ممنوح» (وإلا «افتح الإعدادات» وامنحه يدويًّا) |
| ٢٫٤ | فعّل لعبة للّوحة، افتحها من اللوبي | يظهر المقبض خلال ثوانٍ؛ أغلقها فيختفي |
| ٢٫٥ | افتح لعبة من **المشغّل** (لا اللوبي) وخدمة اللوحة حيّة | يظهر المقبض (إن كانت الخدمة مغلقة فلن يظهر — معروف) |
| ٢٫٦ | بدّل Wi-Fi/البيانات/عدم الإزعاج من اللوحة | يتغيّر فعلًا؛ وعند الفشل تظهر «لم يتغيّر X» |
| ٢٫٧ | لقطة شاشة وتسجيل ٣٠ث ثم إيقاف | ملفّ في `Pictures/MaxManager` و`Movies/MaxManager` يُشغَّل |
| ٢٫٨ | إيقاف التسجيل بعد ٣ دقائق | يُنتج عدة مقاطع ولا تبقى حلقة معلّقة (`adb shell pidof screenrecord` فارغ) |

## ٣) بروفايل اللعبة بلا رفيق الجذر (P3)
اضبط للعبة: عدم الإزعاج = تشغيل، معدّل التحديث = ٩٠، تقليل الاهتزاز = تشغيل. ثم:
```sh
adb shell settings get global zen_mode; adb shell settings get system peak_refresh_rate; adb shell settings get system haptic_feedback_enabled
adb logcat -d | grep -E "INAPP_PROFILE|PANEL_WRITE"     # أو sysmon.log إن كان لديك جذر
```
| # | الخطوة | المتوقَّع |
|---|---|---|
| ٣٫١ | افتح اللعبة | `INAPP_PROFILE_APPLIED written=N verified=N` (N = عدد المفاتيح)، والقيم أعلاه تغيّرت |
| ٣٫٢ | اخرج إلى الرئيسية | `INAPP_PROFILE_RESTORED complete=true` والقيم عادت لما كانت |
| ٣٫٣ | `zen_mode` = ٢ قبل الدخول | `INAPP_PROFILE_SKIPPED knob=DND reason=zen-mode-already-on` ولا يُخفَّض |
| ٣٫٤ | **أنهِ التطبيق قسرًا أثناء اللعب** (`adb shell am force-stop nd.max`) ثم افتحه | `INAPP_PROFILE_RESTORED` عند الإقلاع والقيم عادت (اختبار اللقطة المحفوظة) |
| ٣٫٥ | أطفئ الشاشة أثناء اللعب ثم أشعلها | يُسجَّل استرجاع ثم تطبيق؛ لاحظ وميض عدم الإزعاج (خطر مُعلن) |
| ٣٫٦ | بدّل الوضع Shizuku ⇄ Auto من البطاقة | تُعاد قراءة وثيقة البروفايلات من المالك الجديد؛ لا تضيع بروفايلات الجذر |
| ٣٫٧ | في Shizuku: افتح شاشة تحرير بروفايل | الصفوف الجذرية معطّلة + سطر الشرح؛ عدم الإزعاج ومعدّل التحديث والاهتزاز فعّالة |

## ٥) الاختصار والأيقونة المستقلة (HyperOS)
```sh
adb shell cmd package resolve-activity --brief -c android.intent.category.LAUNCHER nd.max
adb shell dumpsys shortcut | grep -A6 static_game_lobby
```
| # | الخطوة | المتوقَّع |
|---|---|---|
| ٥٫١ | ضغطة مطوّلة على أيقونة التطبيق | يظهر «لوبي الألعاب»؛ والضغط عليه يفتح اللوبي |
| ٥٫٢ | خيارات اللوبي ← «أضف للدسكتوب» | يظهر مربّع المشغّل، أو تظهر رسالة HyperOS (إذن «اختصارات الشاشة الرئيسية») |
| ٥٫٣ | فعّل «أيقونة مستقلة» | تظهر «لوبي الألعاب» في درج التطبيقات خلال ثوانٍ، وتفتح اللوبي |
| ٥٫٤ | عطّلها | تختفي من الدرج |

## ٦) الإقلاع البارد وقرار النشاط الخفيف
من تقرير المسبار (`cold start`): وسيط `TotalTime` للتطبيق وللوبي من الاختصار. **ملاحظة:** هذا زمن أول إطار للنشاط لا زمن جاهزية اللوبي؛
لجاهزية اللوبي استعمل `adb logcat | grep -i "Displayed nd.max"` وقارن بإطار المحتوى.
**قاعدة القرار:** إن كان وسيط اختصار اللوبي ≤ وسيط التطبيق + ٢٠٠ms فلا يستحق نشاطًا مستقلًّا؛ وإن زاد عنه كثيرًا فالنشاط الخفيف هو الخطوة التالية.

## ٧) التسجيل
انسخ تقرير المسبار وجداول ٢–٥ (✓/✗ + ملاحظة) إلى إدخال `HANDOFF.md` جديد، وانقل كل ✗ إلى `KNOWN_ISSUES.md` برقم.
