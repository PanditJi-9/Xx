# SD Maid — تحليل عميق وخطة إضافات «العناية بالتخزين» (SDMAID-01)

> **الطلب (المالك):** «قم بتحليل عميق لكي تضيف ميزة وكل تفصيلة لدينا» عن `github.com/d4rken-org/sdmaid`.
> **حالة الرخصة — البوّابة الأولى:** مستودع SD Maid (الإصدار الأول، المؤرشف) **بلا رخصة** ⇒ **صفر نقل كود، صفر نسخ نصّ**؛
> التحليل **وظائفي** (سلوك تصفه الويكي) وإعادة البناء بأسلوبنا (ADR-55 · ADR-77). و`sdmaid-se` (الإصدار الثاني)
> **لم تُثبت رخصته بعد** — لا يُقترب منه حتى تُقرأ (سابقة `Wavelet`).
> **المنهج:** ويكي المستودع (٢١ صفحة) فُحصت صفحة‑صفحة، وقوبل كل بند بقاعدة الكود عندنا (المقيس يوم التحليل).

## ١) جرد الأدوات كما تصفها الويكي

| الأداة | الجوهر والتفاصيل | عندنا اليوم | الفجوة |
| --- | --- | --- | --- |
| **Overview** | لوحة كل مناطق التخزين (عام/خاص، أساسي/ثانوي، OTG، `/data` `/cache` `/system` — وما لا يُقرأ بلا جذر يُعرض بحجمه المقيس) + صفوف استخدام | حر/مستخدم أساسي + «قريب من الامتلاء» | جزئي |
| **QuickAccess** | صفّ لكل أداة: ضغطة تدقّق، ثانية تنفّذ؛ خيار **Singlepass** (فحص+حذف بلا تأكيد)؛ ويدجت | زرّ تنظيف واحد لفئاتنا | جزئي |
| **AppCleaner** | ملفات «قابلة للتخلّص» منسوبة لتطبيق مثبَّت: الكاش الرسمي + مواضع كاش غير قياسية + مجلدات مضافة يدويًّا؛ **الأساس-كل-تطبيق**؛ وبلا جذر يوجّه المستخدم لشاشة النظام (وصولية) | فئتا AppCaches/SharedCaches + ورقة تطبيق (مسح كاش/بيانات) | جزئي |
| **CorpseFinder** | مسح **مواضع متعددة**: `Android/data` · `Android/obb` · **مجلدات التخزين العام بأسماء حزم مُزالة** · `.trashed` · Dalvik-cache · App-data — كلها تُطابق بتطبيق مثبَّت، وغير المطابق = جثّة، مع **وسوم خطر** (Dalvik أخضر — كسره مؤقّت؛ App-data أحمر — فقد بيانات) | فئتا الجثث: `Android/data`+`obb` | امتداد |
| **SystemCleaner** | محرّك **مرشّحات ملفات** لا يعرف التطبيقات: مرشّحات افتراضية (مجلدات فارغة · dropbox · كاشات نظام · سجلات · temp…) بألوان خطر + **مرشّحات مستخدم** JSON تُستورد/تُصدَّر بشروط | ٧ فئات ثابتة | جزئي (لا مرشّحات مخصّصة) |
| **Databases** | مسح كل sqlite ثم **VACUUM** (إزالة صفحات فارغة بلا فقد بيانات)؛ إعدادات: مواضع البحث، symlinks، تضمين النظام، **تخطّي التطبيقات العاملة** (SIGSTOP بجذر)؛ استثناء فردي | لا شيء | **كاملة** — تحتاج ثنائية `sqlite3` (نطوّرها أو نكتفي بوجودها) |
| **Duplicates** | حجم → بصمة MD5، **ضمان بقاء نسخة** إلزاميًّا، **معايير اختيار قابلة الترتيب**: مفهرس MediaProvider · موقع التخزين · عمق المسار · تاريخ التعديل؛ **Prune** لفهرس الوسائط بعد الحذف؛ مواضع بحث؛ جدولة | لا شيء | **كاملة** |
| **AppControl** | قائمة بحث بالوسوم (System/Frozen/Stopped/Boot)؛ تشغيل · قتل · فرض إيقاف · **تصدير APK** · تجميد · نقل · حذف (مع تنظيف جثث) · **إعادة ضبط التطبيق** (بيانات + مجلدات) · **مدير المستقبلات (Autostart)** بالجذر | تجميد/ديبلويت + مسح بيانات | جزئي |
| **Exclusions** | استثناءات **نصّية/Regex** موسومة بالأدوات؛ استيراد/تصدير JSON؛ تُمحى نتائج الفحص بعد تعديلها (تُطبَّق عند الفحص) | لا شيء | **كاملة** — وقاعدة لكل ما بعده |
| **Explorer** | مدير ملفات: فتح-بأي-تطبيق · نسخ/نقل بمهامّ · إنشاء استثناء · حذف · **حجم مُخصَّص allocated** · تنقّل بالجذر | لا يوجد | خارطة |
| **Searcher** | اسم ببدل ضمني (`*berry*`) · حساسية حالة · ملفات فقط · بحث من `/` مع تخطّي `proc/dev/sys/acct` · **عمر** (أدنى/أقصى) يدمج مع Last-Modified ويتحوّل لترتيب زمني؛ إجراءات سياق | لا شيء | **كاملة** |
| **Statistics** | رسوم ما وفّره كل أداة + **سجل العمليات الجراحية**؛ مدى احتفاظ وحجم وتصفير | قياس موفَّر دوريّ (بلا سجل دائم) | جزئي |
| **Scheduler** | مهامّ مجدولة لكل أداة (فحص+تنفيذ)، إعادة تشغيل كاملة/واجهة؛ تخطّي البطارية المنخفضة · **على الشاحن فقط**؛ ±10د لتوفير الطاقة | `MaxBackupScheduler` (نمط WorkManager قائم) | جزئي |
| **Settings/FAQ** | إعدادات عامة وأسئلة | قائم | — |

**تفاصيل تصميمية ثمينة تُحفظ (لا تُنسى):**
- **SystemCleaner:** اجتياز متعدد **لازم** للمجلدات الفارغة المتداخلة (A/B/C يحتاج ٣ دورات) — نتحقق أيّة دورة نطبّق.
- **Duplicates:** ألوان/معايير الاختيار **مرتبة تنازليًّا** والترتيب يُسحب؛ الافتراضيات: **المفهرس يُبقى**، التخزين الأساسي مفضّل، المسار الضحل مفضّل، الأقدم يُبقى.
- **Databases:** «تخطّي التطبيقات العاملة» افتراضي **سلامة أولًا** — والعامل الجذري يسمح بـSIGSTOP فيصير أوسع وأأمن.
- **Exclusions:** أثرها **عند الفحص** لا الحذف ⇒ تعديلها يلزمه إعادة فحص (يُعلن في الواجهة).
- **AppCleaner بلا جذر عبر الوصولية:** توجيه المستخدم لشاشة النظام آليًّا — صار عندنا خدمة وصولية الآن (من نقل الجزيرة) ⇒ ممكن لاحقًا.

## ٢) خطة الموجات (تُنفَّذ بالترتيب — كل موجة تُقاس وتُسلَّم مستقلة)

| الموجة | النطاق | ملاحظة تقنية |
| --- | --- | --- |
| **S1** | **المكرّرات** (محرّك حجم→بصمة، ضمان بقاء نسخة، معايير اختيار، حذف دفعة + تقرير، Prune للوسائط) + **امتدادات الجثث** (التخزين العام بأسماء الحزم المُزالة · `.trashed`) + **temp** (`/data/local/tmp` و`/cache` بجذر) + **سجل الإحصاءات** (وقت/فئات/موفَّر + مدى احتفاظ + تصفير) | كل الحذف يمرّ بمحرّك القياس القائم (قبل/بعد)؛ والحذف عبر `PrivilegeManager` وحده |
| **S2** | **الاستثناءات** (نصّي/Regex موسوم بالأدوات + استيراد/تصدير JSON + افتراضيات) ثم **ربطها** بكل الفئات والمكرّرات | تُطبَّق عند الفحص — تُوثَّق قاعدة «أعد الفحص» |
| **S3** | **الباحث** (اسم/عمر/حجم، جذر اختياري، تخطّي الأنظمة) | `find` بالجذر + مشي Kotlin لما نقرأه |
| **S4** | **VACUUM لقواعد البيانات** | قرار ثنائية `sqlite3` (ملكية عامة · NDK) أو كشف وجودها أصلًا وعرض شرطي |
| **S5** | **AppControl+**: تصدير APK · إعادة ضبط موسّعة · مدير مستقبلات البوت | `pm`/الجذر |
| **S6** | **المجدول** (WorkManager: على الشاحن/بطارية كافية) بواجهة فئات S1 | يُبنى على نمط `MaxBackupScheduler` |
| **S7** | **QuickAccess** (صفوف أدوات بضغطة/ضغطتين + Singlepass) | ويدجت آخرًا |
| **S8** | **Explorer-lite** + مرشّحات مستخدم JSON | قرار لاحق |

## ٣) قواعد السلامة الملزمة لكل موجة
1. لا `rm` مباشر: كل حذف يمرّ بمحرّك القياس والتقرير القائمين في «العناية بالتخزين».
2. المكرّرات: **يستحيل** حذف كل النسخ — «ابقِ واحدة» قاعدة داخل المحرّك نفسه، لا في الواجهة.
3. الجذر عبر `PrivilegeManager` فقط (ADR-11 يبقى)، وكل ما يحتاج جذرًا يُعطَّل بصراحة بلا جذر — كما اليوم.
4. النصوص الجديدة **en+ar فقط** (§0.2)، وكل ميزة باختباراتها المناسبة، والبوابات الست قبل أي تسليم (§0.1).
