# CONTROL_TIERS — نواة واحدة وثلاثة مقاعد

> **القرار الحاكم (أمر المالك):** نبني **نسخة أصلية من الصفر** سلوكها مطابق لمنظومة RedMagic، لكنها
> **عامة على كل هاتف**، وتعمل بثلاثة أوضاع: **بلا روت · Shizuku (ADB) · روت**. ولا نرقّع المنظومة
> الأصلية ولا نعدّل أجزاء منها — نستبدلها بنواة واحدة تعمل على الأجهزة الثلاثة.

---

## 1. الفكرة في سطر واحد

**كل قدرة تُعرَّف مرة واحدة، وتُنفَّذ بثلاثة مقاعد (`Seat`) خلف واجهة واحدة؛ والتطبيق لا يعرف بأي مقعد
يعمل.** الترقي من «بلا روت» إلى «روت» **لا يغيّر سطرًا في تطبيق واحد** — يغيّر ما تستطيعه القدرة فقط،
وما لا تستطيعه يُعلَن `UNSUPPORTED` بسببه، ولا يُعرض مفتاح وهمي.

وهذا هو الفرق الجوهري عن الترقيع: الترقيع يضيف `if (root) …` في كل شاشة؛ نحن نضيف **مقعدًا** في مكان واحد.

## 2. المقاعد الثلاثة — ما تستطيعه فعلًا (لا ما نتمنّاه)

| القدرة | بلا روت | Shizuku (uid 2000) | روت (uid 0) |
| --- | --- | --- | --- |
| تراكب خاص بنا (`TYPE_APPLICATION_OVERLAY`) | ✅ بإذن `SYSTEM_ALERT_WINDOW` | ✅ نفسه | ✅ نفسه |
| اكتشاف اللعبة في المقدمة | ✅ `UsageStatsManager` بإذن | ✅ + `dumpsys activity` | ✅ + أي استعلام |
| آلة الجلسة (خمس حالات) | ✅ كاملة | ✅ | ✅ |
| قراءة الترددات/الحرارة (`sysfs`) | ✅ غالبًا للقراءة | ✅ | ✅ |
| **كتابة** ترددات/حكّام (`scaling_governor`, `scaling_max_freq`) | ❌ (`SELinux` يمنعنا) | ⚠️ **جزئي**: ما يملكه `shell` فعلًا — يُقاس لكل جهاز | ✅ |
| `game mode` عبر `GameManager`/`cmd game` | ⚠️ لإطارنا فقط | ✅ لكل حزمة | ✅ لكل حزمة |
| `appops`/`pm grant` لحزم أخرى | ❌ | ✅ | ✅ |
| `cgroups`/`taskset` لعزل لعبة | ❌ | ⚠️ جزئي | ✅ |
| تعديل حزم النظام/إخفاء تطبيقات | ❌ | ⚠️ | ✅ |

**قاعدتان مقيسستان لا مُدَّعتان:**
1. **الجدول أعلاه فرضية تصميم حتى يُقاس على جهاز** — عمود Shizuku خصوصًا يختلف بين نواة وأخرى.
   كل صفّ يُختبَر ويُسجَّل نتيجته في `DEVICE_MATRIX.md`؛ وما لم يُقس يبقى `UNKNOWN` لا `✅`.
2. **القراءة ليست كتابة.** القدرة تحمل `Access` (`NONE`/`READ_ONLY`/`READ_WRITE`) كما في `:core`؛
   فتطبيق يعمل بلا روت يعرض القيمة الحقيقية ويُعطّل الكتابة **بسبب مكتوب**، لا يعرض 0 ولا يقلّد نجاحًا.

## 3. الشكل المعماري

```
                    ┌─────────────────── تطبيقات (14 وحدة) ──────────────────┐
                    │  Gamespace · GameAssist · GameTurbo · … (رفيعة)          │
                    └───────────────────────────┬────────────────────────────┘
                                                │  :kit  (تراكب · لوحة · جلسة · مقياس)
                    ┌───────────────────────────┴────────────────────────────┐
                    │  :core   القدرات · الحكّم (arbiter) · GuardedNode       │
                    │          ValuePolicy · Access · SessionMachine          │
                    └───────────────────────────┬────────────────────────────┘
                                                │  ControlSeat (واجهة واحدة)
              ┌─────────────────────────────────┼─────────────────────────────────┐
       LocalSeat (بلا روت)              AdbSeat (Shizuku)                    RootSeat (su)
       APIs عامة فقط                   Binder إلى خدمة Shizuku               shell su
```

### 3.1 واجهة المقعد

```kotlin
interface ControlSeat {
    val tier: Tier                      // LOCAL · ADB · ROOT
    fun canRead(node: NodeRef): Boolean
    fun read(node: NodeRef): String?
    /** يرمي/يُعيد NotRealized — ولا يُعيد true كاذبة أبدًا (الحكمة المقيسة من MaxManager). */
    fun write(node: NodeRef, value: String): WriteOutcome
    fun exec(command: List<String>): ExecResult   // LOCAL يُعيد Unsupported
}
```

`LocalSeat` لا يملك `su`، و`AdbSeat` لا يملك `su`، و`RootSeat` يملك الاثنين — لكن **العقد واحد**،
و`GuardedNode` هو من يتحقق بإعادة القراءة ويتراجع، أيًّا كان المقعد.

### 3.2 الاختيار والترقية

- `SeatNegotiator` يجرّب بالترتيب `ROOT → ADB → LOCAL` مرة واحدة عند الإقلاع، ويسجّل **سبب** كل رفض
  (لا `su`، Shizuku غير مثبّت، الإذن مرفوض). الطلب اليدوي من المستخدم (`tier=ADB`) يُحترم.
- لا توجد إعادة محاولة صامتة كل ثانية: محاولة `su` متكررة تُستهلك بطارية وتُزعج المستخدم.
- تخفيض آمن: قدرة تحتاج `ROOT` على مقعد `ADB` ⇒ `CapabilityState.DEGRADED` مع
  `requiredTier` و`currentTier` — وهذه أول مرة نحتاج فيها حالة سادسة، تُضاف بـADR لا بالالتفاف.

## 4. لماذا هذا أسرع طريق (وليس مجرد تنظيف)

| البديل | كلفته الحقيقية |
| --- | --- |
| فرع لكل وضع داخل كل شاشة | 3 × 14 تطبيقًا × كل عنصر تحكم = مئات الفروع، وكل عطب يُصلح ثلاث مرات |
| نسختان منفصلتان (عادية/روت) | شيفرتان تتباعدان، وكل إصلاح يُنسى في إحداهما |
| **مقعد واحد + قدرة واحدة** | الشاشة تُكتب مرة، والفرق كله في سبعة أسطر من `SeatNegotiator` |

ومعه مكسب اختبار: `FakeSeat` لكل طبقة في `:core` ⇒ **كل مسارات الأوضاع الثلاثة تُختبر على JVM بلا جهاز**
في CI. الجهاز لا يُسأل إلا عمّا لا يُقاس في CI: هل `shell` يكتب هذه العقدة على هذه النواة؟

## 6. ما لا يُدَّعى

- «يعمل على كل هاتف» تعني: **يبني ويعمل بلا انهيار**، لا «كل ميزة متاحة» — التوافر يقرّره المقعد والعتاد.
- لا مقعد يخترق `SELinux` ولا يرفع صلاحية أعلى مما مُنح؛ `RootSeat` يستعمل `su` الموجود، فإن غاب فالمقعد غائب.
- Shizuku ليس روتًا: هو `shell`، وهو مقيّد بما تسمح به النواة لـ`shell` — ويُقاس ولا يُفترض.
