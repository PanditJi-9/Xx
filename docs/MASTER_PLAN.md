# MASTER_PLAN — RedLab: إحياء Game Turbo بالبورت لا بإعادة الاختراع

> **الخطة الحاكمة (النسخة ٣).** تُلغي ما قبلها من صيغ «نواة جديدة» و«قشور رقيقة» و«شريحة عمودية».
>
> **عقيدة المالك:** «لا تعِد بناء شيء موجود أصلًا دون ضرورة… الأولوية دائمًا: 1) استخدام الأصل،
> 2) تكييف الأصل عند الضرورة، 3) إعادة تنفيذ الجزء غير القابل للنقل فقط، 4) اختبار الوظيفة الحقيقية
> دون محاكاة أو نجاح وهمي.»
>
> **المنتج:** تجربة RedMagic Game Turbo مُعادة التجميع في RedLab — تُقدَّم للناس كـ«Game Turbo الأصلي
> بعد تحسينه وتعديله»، تعمل على أجهزة Android المختلفة، بثلاثة أوضاع (Root · Shizuku · بلا Root).
>
> **والبنية الإلزامية:** **مجلد مستقل لكل تطبيق** (`redlab/apps/gamespace`، `redlab/apps/gameassist`، …)
> حتى يستطيع المالك تحسين أي تطبيق بمفرده لاحقًا دون مساس بالبقية.

---

## 1. ماذا نأخذ من الأصل (لا «نبني مثيلًا»)

| المادة | القرار |
| --- | --- |
| Java/Kotlin/C++ | **يُنقل ويُبنى** ما دام يترجم؛ لا إعادة كتابة لمنطق سليم |
| XML · Layouts · Drawables · Styles | تُنقل كما هي (apktool) |
| Icons · Fonts · Animations · Sounds | تُنقل كما هي |
| Services · Receivers · Providers · Manifest · Permissions | تُنقل كما هي مع تعديل الحزمة والتوقيع فقط |
| Binder · AIDL · JNI · `.so` | تُنقل؛ والرابط `System.loadLibrary` يُصحَّح للاسم الجديد فقط |
| Game logic · Controllers · HUD · Touch | تُنقل كما هي |
| Configurations | تُنقل، وما يخصّ RedMagic يُقادَم في طبقة التوافق |

**ما يُعاد تنفيذه فقط** (البند 3 من العقيدة): ما يعتمد على خدمات/أصناف `cn.nubia.*` أو `com.zte.*`
غير الموجودة على هاتف آخر، أو على صلاحيات نظام لا نملكها. وهذا يُحلّ بـ**طبقة توافق بأسماء الحزم
الأصلية** (كما فعلنا مع `RootCommands`/`DaemonIpc`): نكتب الصنف الناقص بنفس التوقيع، فيعمل الكود
المنقول بلا تعديل سطر واحد فيه.

## 2. النطاق

| البند | القرار |
| --- | --- |
| البداية | `gamespace` (المكتبة/الجلسة) ثم `gameassist` (اللوحة) ثم مشتقاتهما التي يستدعيها الكود فعلًا |
| الـ23 تطبيقًا | **مصدر مواد**، لا منتجات مستقلة |
| الإغلاق | محسوب بـ`tools/gt_closure.py`: 2 أساس + 9 تابعة + 6 للمراجعة + 6 بلا حافة |
| ما لا يُستبعد | لا مكوّن يُهمل بلا دليل مكتوب في `REBUILD_LEDGER` |

## 3. خطّ البورت (لكل تطبيق، مرة واحدة)

```
APK
 ├─ apktool  → res/ · AndroidManifest.xml · assets/           (مواد تُنقل كما هي)
 ├─ jadx     → sources/ (java)                                 (كود يُنقل ويُبنى)
 ├─ unzip    → lib/<abi>/*.so · assets/                        (ثنائيات تُنقل)
 └─ triage   → ثلاث قوائم:
       PORT_AS_IS    كود/موارد تعمل بعد تغيير الحزمة فقط
       ADAPT         يحتاج: R · package · permission · API أحدث · مسار ملف
       REIMPLEMENT   يعتمد على cn.nubia.* / com.zte.* / صلاحية نظام  → عقد في :compat
```

**قاعدة الأرقام:** كل ملف من `sources/` يُسجَّل في `REBUILD_LEDGER.md` بحالته، وعدد صفوف
`PORT_AS_IS` هو مقياس التقدّم الحقيقي — لا عدد ما كتبناه بأيدينا.

## 4. طبقة التوافق `:compat` (أسماء أصلية، تنفيذ لنا)

- تُوضع في `redlab/apps/<app>/src/compat/` أو في `redlab/compat/` إن اشترك فيها أكثر من تطبيق.
- **العقد**: الحزمة والصنف والتوقيع كما في الأصل (`cn.nubia.gameassist.GameAssistManager`…)، والتنفيذ
  يسقط على `ControlSeat` (Root/Shizuku/Local) أو على API عام.
- **لا تغيير سلوك**: ما لا يمكن تنفيذه يُعيد نفس خطأ الأصل (`null`/`false`/استثناء) لا بديلًا صامتًا.
- **جدول تغطية**: `docs/COMPAT_COVERAGE.md` يعدّ كم صنفًا طُلب، كم نُفِّذ، كم بقي.

## 5. ثلاثة أوضاع بمقبس واحد

`RootCommands.execute` (مُنفَّذ أصلًا في شجرة البورت) هو المقبس الوحيد: التطبيق يركّبه على مقعد
`Root` أو `Shizuku` أو `Local` عند الإقلاع (`docs/CONTROL_TIERS.md`). لا `if (root)` في أي شاشة،
ولا نسختان من التطبيق.

## 6. هيكل المجلدات (مطلب المالك)

```
redlab/
  apps/
    gamespace/      ← APK مستقل: manifest · res · ported sources · compat
    gameassist/     ← مستقل
    gamefloat/      ← مستقل (يُفتح عند الحاجة المقيسة)
  kit/              ← محرّكات مشتركة (تراكب · لوحة · جلسة · مقياس) — لا تُكرَّر في كل تطبيق
  core/             ← قدرات/مقاعد/جلسة (مختبَرة JVM)
  hardware/         ← محرّك MaxManager المنقول (قيد الفتح)
  compat/           ← عقود Nubia/ZTE المشتركة
```

## 7. البوابات (لا ادّعاء بلا دليل)

| البوابة | ما تثبته |
| --- | --- |
| `:apps:<x>:assembleDebug` | الملفات المنقولة تُترجم معًا (لا «ينبني» فقط) |
| `:apps:<x>:testDebugUnitTest` | المنطق المنقول يعمل باختباراته أو اختباراتنا |
| تثبيت على جهاز + سيناريو | الوظيفة الحقيقية: فتح لعبة ← جلسة ← لوحة ← تحكم ← خروج |
| `REBUILD_LEDGER` | كل ملف بحالته ودليله؛ ولا صفّ يتجاوز `SCAFFOLDED` بلا دليل |
| `gt_closure --assert` | لا تبعية مستبعدة بلا سبب مكتوب |

**ولا نجاح وهمي:** إن لم تعمل وظيفة على جهاز، تُسجَّل `TESTED_DEVICE = ✗` بحدودها، ولا تُوصف بأنها تعمل.

## 9. ما يبقى صريحًا

- **الحقوق**: نشر كود/موارد Nubia كما هي يعني أن المنتج **عمل مشتق** منها؛ القرار قرار المالك،
  ويُوثَّق في `PROVENANCE.md` بصدق (لا يُدَّعى «مكتوب من الصفر»).
- **العتاد**: كل ادّعاء تشغيل يحتاج جهازًا؛ CI يثبت الترجمة والاختبارات لا السلوك.
- **الوقت**: لا وعد بيومين؛ كل محطة تُقاس ببوابتها. والسرعة تأتي من البورت نفسه لا من الاستعجال.
