# نظام الواجهة — رأي واحد

> الهدف البصري: **كونسول مختبر**. سطح OLED هادئ، خطوط شعرية، الرقم الجدولي هو البطل،
> لون تمييز واحد، لون خطر واحد، وحركة قصيرة هي انتقال حالة لا ارتداد.
> لا قالب Material عام، ولا زجاج/نيون، ولا لون لكل قسم.
>
> **الملحق بالثيم القائم:** `MaxManagerTheme` + `ui/design/MaxTokens.kt`. لا نظام موازٍ.

### الحالات الإلزامية لكل نمط

تحميل · تحديث · فراغ **بسبب وفعل** · خطأ **بخطوة تالية** · لا صلاحية · غير مدعوم · قفل حراري · قيمة قديمة · قيد الإرسال · **مُتحقق** · فشل **وعادت القيمة**.

الموجود اليوم: `ContentStateComponents` يغطي التحميل/الفراغ/الخطأ. الناقص المعلن: «قيد الإرسال» و«مُتحقق» نمطٌ موحّد عبر الشاشات (موجود داخل شاشات التحكّم فرادى).

## 4. المعجم (داخلي ← واجهة ← صيغة الخطر)

| المصطلح الداخلي | كلام الواجهة (ar / en) | ملاحظة |
| --- | --- | --- |
| `ControlOwnership.Owner.SAFETY` | الحماية الحرارية / Thermal safety | لا تُختصر إلى «SAFETY» |
| `RECOVERY` | الاسترداد / Recovery | أعلى السلّم |
| `PER_APP` | ملف التطبيق / App profile | لا «PER_APP» |
| `MAX_AI` | MAX AI | اسم منتج، لا يُترجم |
| `GLOBAL_PROFILE` | الملف العام / Global profile | الاختيار اليدوي يسكن هنا |
| `SYSTEM` | النظام / System | أدنى السلّم |
| `lease` | مفتاح مُدار / Managed control | لا «lease» |
| `ownerToken` | — | **لا يُعرض**؛ يُعرض الاسم البشري فقط |
| `apply → verify → rollback` | طُبِّق وتُحقّق / فشل وعادت القيمة | لا «success» قبل التحقق |
| `MaxDataTrust.Stale` | آخر عيّنة / Last sample | لا «مباشر» لقيمة قديمة |
| `MaxDataTrust.Unsupported` | غير مدعوم / Not supported | بديلها شرطة `—` لا صفر |

**صيغة الفعل الخطر:** فعل أمر + العاقبة في جملة واحدة:
> «اكتب ٦٠ هرتزًا على اللوحة؟ سيُقرأ مرة أخرى للتحقق، وإن رُفضت القيمة تُعاد السابقة.»

لا «هل أنت متأكد؟». ولا «نجاح» أخضر قبل `verified`.

## 5. أفكار القسم ٣ — المقبول والمرفوض

| # | الفكرة | القرار | السبب (اختبار الأربع جمل) |
| --- | --- | --- | --- |
| ١ | البداية وضع لا قائمة | **مقبولة جزئيًّا (نُفِّذ شقّها)** | الألم: لا تعرف من يحكم. الثانيتان: الحرارة والوصول والحكّام. الآمن إن فشلت الكتابة: العرض لا يكتب. أذكى من شاشة جديدة: يضيف سطرًا لا مسارًا. |
| ٢ | الفعل بجانب الأثر | مقبولة — **لم تُنفَّذ** | تحتاج ربط كل مقبض بقارئه الحيّ؛ تُبنى شاشةً شاشةً لاحقًا. |
| ٣ | فرق قبل تطبيق الحزمة | **مرفوضة الآن** | لا يوجد في الشجرة نظام «حزمة ملفات/تغييرات» أصلًا؛ بناؤه استيراد ميزة غير موجودة. |
| ٤ | من الرقم إلى المقبض | مقبولة — **لم تُنفَّذ** | تحتاج نموذج قراءة موحّدًا لكل رقم؛ تُترك لشريحة تالية. |
| ٥ | أوامر بالقصد | **مقبولة جزئيًّا (نُفِّذت كلمات القصد)** | تحتاج فهرس نوايا معرَّبًا واختبارات؛ «شحن» و«٦٠» و`bypass` تُطابق الآن ٦٤ وجهة (كل وجهة معروضة تُفتح بلا معرّف)، والجملة الكاملة لم تُفهم بعد. |
| ٦ | الذاكرة العضلية | **مقبولة ومنفَّذة ضمنًا** | لم يتغيّر مسار واحد؛ الشريط الجديد لا يزيح صفًّا. |
| ٧ | الفشل مشهد لا Toast | مقبولة — **جزئيًّا** | `MaxErrorState` موجود؛ تعميم «فشل وعادت القيمة» لم يكتمل. |
| ٨ | الحكّام ظاهرون | **مقبولة ومنفَّذة** | الألم: قرار يُرفض بلا سبب. لا تغيير أولوية. |
| ٩ | الملف نية | **مرفوضة** | لا نظام ملفات/مواقف في الشجرة؛ اختراعه يخالف §١.٦. |
| ١٠ | زمن قصير | مقبولة — **جزئيًّا** | `MaxLiveScreen` يعرض «آخر عيّنة»؛ الباقي يحتاج تعميم قاعدة §ن-٤. |
| ١١ | لغة أفعال | **مقبولة** | الجدول في §٤ أعلاه. |

### ما ليس عبقرية (مرفوض صراحةً)

- مساعد يشرح الإعدادات · هاتف يدور في المشهد · عدّادات لا تغيّر قرارًا · جسيمات/ضباب ·
  لون لكل قسم · إخفاء الأدوات خلف بطاقة «ذكية» · أي ابتكار يكتب خارج المراجِع.

## 6. الكثافة والوصول

- **ثلاث طبقات لا تطبيقان:** الوجه (وضع + فعل) · التفاصيل (نطاق) · الخبراء (`rememberAdvancedMode` + بحث + سجلات). «متقدّمة» قسم ظاهر.
- **RTL:** الأسهم `AutoMirrored`؛ لا محاذاة يسارية مثبّتة في مكوّن جديد؛ الأرقام لاتينية.
- **TalkBack:** كل شريحة حاكم تحمل `contentDescription` = الاسم + «يملك مفتاحًا» بدل قراءة الشارة لونًا.
- **الخطر:** لا يُلاصق التنقل؛ فعله بعيد عن الإبهام المتكرر، ولونه وحده لا يكفي.
- **الحركة:** تُحترم إعداد تقليل الحركة (`rememberAnimationsEnabled`)؛ لا حركة في الخلفية.

## 7. ممنوع بصريًا (قائمة قصيرة ملزمة)

عداد بلا قرار · تدرّج/زجاج على حساب الرقم · لون لكل قسم · بطاقة داخل بطاقة ·
مصطلح كود في الواجهة · نجاح أخضر قبل التحقق · نقل الخطر إلى مكان أسهل بلا تقوية التأكيد ·
طباعة `ownerToken` أو `lease.key` كما هي في واجهة المستخدم العادي.
