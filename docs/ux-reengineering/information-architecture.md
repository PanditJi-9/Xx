# بنية المعلومات المعتمدة

> بنية واحدة، لا بدائل متروكة. كل نقل هنا يقول: الحالي، الجديد، السبب، ماذا يُفقد،
> كيف تبقى المداخل القديمة، وكيف تُتحقق الفكرة. ما لم يُبنَ معلَّم **«لم يُنفَّذ»**.

---

## 1. الشكل المعتمد

```
┌ سطح الأقسام الأربعة (HorizontalPager، لا يُعاد بناؤه) ─────────────────┐
│ الآن        التطبيقات      التحكّم            الإعدادات                  │
│ وضع الجهاز   قائمة + بحث    الحكّام ثم النطاقات  النظام والمظهر والنسخ    │
└──────────────────────────────────────────────────────────────────────────┘
        │            │              │                    │
        │            │              ├─ ١٠ نطاقات (شاشة لكل نطاق)
        │            │              ├─ أدوات متقدّمة (ظاهرة، لا سرّية)
        │            │              └─ موجد الشاشات (بحث)
        │            └─ إعدادات تطبيق واحد
        └─ تفاصيل الجهاز، MAX AI، البثّ الحيّ
```

**قاعدة التوزيع:**

| الطبقة | ما يوضع فيها | أين تظهر |
| --- | --- | --- |
| الوجه | وضع الجهاز، الحكّام، الفعل المتكرر | الآن + أعلى التحكّم |
| التفاصيل | نطاق واحد، قيمته الحالية، مقبضه | شاشة النطاق/الأداة |
| الخبراء | مقابض دقيقة، بحث، سجلّات، تشخيص | «متقدّمة» ظاهرة + `Diagnostics` |

**لا يتغيّر:** المسارات (`MaxDestination`)، سلّم الأولويات، بوابة الكتابة، الخدمات الخلفية، الحماية الحرارية.

---

## 2. النقلات المعتمدة

### ن-١ · رفع «من يحكم الآن» إلى التحكّم — **نُفِّذ**

| البند | التفصيل |
| --- | --- |
| الحالي | بطاقة إنجليزية داخل `Diagnostics` تطبع `lease.key` و`ownerToken` خامًّا |
| الجديد | شريط سلّم الأولوية في أعلى صفحة التحكّم (ثابت لا يتقادم)، وبطاقة الحكّام النشطين معرَّبة في التشخيص، مع رابط من الشريط إليها |
| السبب | القرار اليدوي يُتخذ في التحكّم؛ ومَن يملك المفتاح يجب أن يُعرف قبله |
| ما يُفقد | لا شيء: التشخيص يحتفظ بكل صفّ، ويزيد عليه أسماء بشرية |
| المداخل القديمة | `diagnostics` كما هو؛ لا ودجة/بلاطة تشير إلى بطاقة الحكّام |
| التحقق | مقارنة النصّ قبل/بعد؛ فحص أن المصدر ما زال `ControlOwnership.snapshot()` وحده |

### ن-٢ · علامة «هذا الصفّ يكتب على العتاد» — **لم يُنفَّذ**

| البند | التفصيل |
| --- | --- |
| الحالي | صفوف التحكّم متطابقة الشكل؛ `MaxRisk` موجود لكنه لا يُعرض |
| الجديد | أيقونة صغيرة + كلمة واحدة («يكتب») على الصفوف التي تنتهي إلى `HardwareControlArbiter`، بلا شرائح خطر متكرّرة |
| السبب | الفعل الخطر يشبه العادي (تشخيص §٣) |
| ما يُفقد | ضجيج بصري محتمل إن عمّت العلامة كل صفّ — لذلك تُشتق من مسار الكتابة لا من تصنيف يدوي |
| المداخل القديمة | لا تتغيّر |
| التحقق | عدّ الصفوف المعلَّمة مقابل `grep` على مستدعي المراجِع |

### ن-٣ · موجد واحد للشاشات والأوامر — **جزئيًّا: نُفِّذت كلمات القصد**

| البند | التفصيل |
| --- | --- |
| الحالي | موجد داخل التحكّم يطابق الاسم والوصف والمكان؛ وبحث مستقل في التطبيقات، وثالث في الملفات |
| الجديد | كلمات القصد («شحن» · «سخونة» · «٦٠» · `bypass`) تُطابق ٦٤ وجهة (كل وجهة معروضة تُفتح بلا معرّف) بلغتين، وترتيبها بعد الاسم وقبل الوصف؛ **ولا تُعرض** في السطر |
| المتبقّي | لا فهم لجُملة كاملة ولا لأمر يُنفَّذ؛ البحث يبقى «يأخذك إلى الشاشة» لا «ينفّذ عنك» |
| المداخل القديمة | زرّ البحث الحالي يفتح الموجد نفسه؛ لا مسار تغيّر |
| التحقق | اختباران في `ScreenFinderTest`: أربع حالات قصد + منع الوجهات المخفيّة |

### ن-٤ · قاعدة صدق واحدة للقيم — **لم يُنفَّذ**

| البند | التفصيل |
| --- | --- |
| الحالي | `MaxTrustChip` في ٣ ملفات؛ شاشات تعرض رقمًا بلا عمر |
| الجديد | كل قيمة من مصدر غير متدفّق تحمل `MaxDataTrust` (اللقطة/القديم/اللا قراءة)، ولا رقم بلا حالة |
| السبب | خرق ADR-07 في مواضع متفرّقة |
| ما يُفقد | سطر إضافي على بعض البطاقات — يُقبل لأنه يمنع قراءة خاطئة |
| المداخل القديمة | لا تتغيّر |
| التحقق | `grep` على `MaxMetricReadout`/`MaxMetricLine` ومقارنة بعدد المواضع التي تقرأ مصدرًا مباشرًا |

### ن-٥ · تنظيم «متقدّمة» كنمط لا كقائمة ثانية — **لم يُنفَّذ**

| البند | التفصيل |
| --- | --- |
| الحالي | «أدوات متقدّمة» مجموعة في آخر التحكّم + قفل في الإعدادات |
| الجديد | يبقى المكان؛ يُضاف لكل صفّ **سبب ظهوره** (خطر/ندرة) عند الوضع المتقدّم فقط |
| السبب | التعقيد طبقة ظاهرة (الطلب §5.6) لا قائمة مبهمة |
| ما يُفقد | سطر شرح إضافي في وضع الخبير |
| المداخل القديمة | لا تتغيّر |
| التحقق | لقطة مقارنة في الوضعين + قصّ عند تكبير الخط |

## 3. خريطة المداخل القديمة (لا تُكسر)

| المدخل | العدد | الوجهة الحالية | بعد إعادة الترتيب |
| --- | --- | --- | --- |
| بلاطة `BypassChgTileService` | ١ | شحن التجاوز | كما هي (مسار `bypass_charging`) |
| بلاطة `ProfileTileService` | ١ | ملف/وضع | كما هي |
| بلاطة `StatusBarTileService` | ١ | شريط الحالة | كما هي |
| ودجات النظام | ٢٢ | `OPEN_ROUTE` → مسار | كما هي؛ تتغيّر **بطاقة الودجة** لا وجهتها |
| اختصار Game Lobby | ١ | `game_lobby` عبر `RemoteFlags.GAMESPACE` | كما هي |
| `nd.max.ACTION_MANAGE` | ١ | `MainActivity` | كما هي |
| موجد الشاشات | ١ | وجهة مسجّلة | يفتح الموجد الجديد نفسه |

**قاعدة:** لا يُحذف معرّف مسار. النقل داخل الشاشة لا يغيّر `route`؛ وما يحتاج إحالة يمرّ بـ`MaxNavActions` + `launchRouteOf` (ADR-02).

---

## 4. ماذا يبقى من الشكل الحالي حرفيًّا

- الأقسام الأربعة و`PrimaryDeck`: الهيكل صحيح ومقيس الأداء (تجهيز الصفحات، بلا تركيب أثناء السحب).
- شاشات النطاقات العشرة: باب الوصول العميق.
- عرضا التحكّم (مختصر/موسّع): يبقيان؛ يُشرح الفرق في مكان واحد بدل تسمية مبهمة.
- `ScreenFinderSheet`: يبقى ويُوسَّع، لا يُستبدل.
- كل الشاشات الفرعية: لا تُدمج ولا تُخفى؛ الترتيب فقط.

---

## 5. القرار الكبير في أربع جمل

| السؤال | الجواب |
| --- | --- |
| أين؟ | الحكّام أعلى التحكّم، ووضع الجهاز يبقى في «الآن» |
| لماذا؟ | القرار يُتخذ في التحكّم، والجهل بمن يملك المفتاح يُقرأ كفشل عشوائي |
| ماذا يُرى؟ | سلّم أولوية ثابت + بطاقة حكّام نشطين معرَّبة + رابط واحد |
| ما الخطر؟ | لا خطر على الكتابة: العرض يقرأ `ControlOwnership.snapshot()` ولا يغيّر مالكًا ولا أولوية |
