## 3. مخاطر مراجعة الكود الجديد (قائمة للمراجع المستقل)

1. `stringResource` داخل `maxGovernanceLadder.map { … }` — نمط موجود في الشجرة (`AudioBackendSection` …)، لكنه يحتاج مُصرّفًا للتأكيد.
2. `MaxCardShell(onClick = onOpenDetails)` — عند `null` لا قابلية نقر ولا دور `Button`؛ عند غير `null` القشرة كلها هدف ٤٨dp+.
3. `R.string.max_gov_*` — ١٥ مفتاحًا في `values/` و`values-ar/` فقط؛ بقية الـ٨٢ لغة ستنقصها المفاتيح (سياسة §٠.٢: لا تعبئة إلا بأمر «زامن»).
4. `MaxOwnerBadge` يستعمل `semantics { contentDescription = … }` — لم يُختبر مع TalkBack.
5. الاختبار الجديد يفترض `ControlOwnership.Owner.priority` ثابتًا؛ إن غُيّر السلّم لاحقًا يجب تحديث الترتيب في `MaxGovernance.kt` (والاختبار سيسقط ليُنبِّه).

## 6. ما يجعل الجولة «مكتملة» بمعنى الطلب §٢

| شرط النجاح | الحالة |
| --- | --- |
| الشاشة الأولى تصف وضع الجهاز | **جزئي** — تصفه فعلًا، وينقصها «من يحكم» (سلّم في التحكّم فقط) |
| الوظيفة من مكانها الطبيعي أو بأمر | **جزئي مرتفع** — القصد يعمل: ٦٤ وجهة بكلمات عربية/إنجليزية، والجملة كاملة تُطابق (إسقاط الحشو · «ال» · تغطية أولًا)؛ ولا تنفيذ أمر («أوقف الشحن» تفتح الشاشة ولا تكتب) |
| الفعل ونتيجته في إطار واحد | **جزئي** — `CpuCoreControlScreen` يعرض نتيجة الإجراء عائمةً (مُطبَّق/محجوب + إعادة قراءة)؛ والقالب الموحّد `MaxWriteResult` لم يُعمَّم على بقية مسارات الكتابة (٧ ملفات تستدعي المراجِع) |
| نمط واحد لكل تفاعل | **جزئي** — `MaxRow` في ٥٠ ملفًا · `MaxGroup` ٦٣ · `MaxCondition` ٣٢ من ١٢٥ ملفّ شاشة؛ والثقة (MaxTrustChip) لم تُعمَّم |
| المبتدئ/الخبير | **غير مقيس** |
| «من يحكم» ظاهر قبل التعديل | **في التشخيص وحده** — أزاله المالك من «الآن» و«التحكّم» (أمرٌ صريح)؛ فالقرار: أقلّ ضجيجًا لا أكثر تغطيةً. ومحميٌّ بـ`OwnerDecisionsGuardTest` |
| مسارات الكتابة لم تتغيّر | **نعم** (قراءة كود) |
| المداخل القديمة لم تنكسر | **نعم** (لا مسار تغيّر؛ لم تُختبر على جهاز) |
| الواجهة أخف أو مساوية | **غير مقيس** — لا إضافة قراءة/رسم متكرّر، لكن لا قياس |

⇒ لا يُقال «اكتملت إعادة الهندسة». الجولة سلّمت: الجرد، التشخيص، البنية، النظام، شريحة الحكّام، وحدودها.
