## 2. أفكار مقبولة ولم تُبنَ

| الفكرة | لماذا لم تُبنَ الآن | الخطوة الصغرى التالية |
| --- | --- | --- |
| الفعل بجانب الأثر | تحتاج لكل مقبض قارئًا حيًّا مربوطًا؛ بناؤها عامّةً يعني قراءة عتاد إضافية | ابدأ بـ`CpuCoreControl`: قيمة حيّة واحدة تحت المنزلقة |
| من الرقم إلى المقبض | تحتاج نموذج قراءة موحّدًا (قيمة/عمر/مصدر/مقبض) | وسّع `MaxMetric` بحقل `controlDestination` اختياري |
| علامة «يكتب» على الصفّ | تحتاج اشتقاقًا من مسار الكتابة لا تصنيفًا يدويًّا | جدول صافٍ: `MaxDestination -> writesHardware` مقيس بـ`grep` |
| موجد بالقصد | **جزئيًّا: التغطية كاملة (٦٤/٦٤ وجهة)** بكلمات عربية/إنجليزية؛ لا فهم لجملة كاملة ولا تنفيذ أمر | التالي: الجملة الكاملة («أوقف الشحن») أو قياس هل الكلمات وحدها تكفي — لا توسيع للكلمات |
| شريط الحكّام غالبًا فارغ | `ControlOwnership` leases قصيرة العمر (تُؤخذ وتُحرَّر حول الكتابة)، فيظهر «لا حاكم آلي» أكثر الوقت — وهو صادق لكنه قد يُقرأ كعمود لا يعمل | يُقاس لاحقًا: هل يُظهر الحالة عند MAX AI فعّال؟ وهل يقرؤه المستخدم؟ |
| قاعدة صدق واحدة | تحتاج مراجعة كل بطاقة تقرأ مصدرًا مباشرًا | ابدأ بالقيم التي تُقرأ مرة واحدة (لقطة إقلاع) |
| الفشل مشهدًا موحّدًا | `MaxErrorState` موجود؛ الناقص «فشل وعادت القيمة» | مكوّن `MaxWriteResult` يعرض `Result` من المراجِع |
| فرق قبل تطبيق الحزمة | لا نظام حزم في المنتج؛ بناؤه استيراد ميزة | لا خطوة — يبقى مرفوضًا حتى يوجد نظام حزم |
| الملف نية | لا نظام ملفات/مواقف أصلًا | لا خطوة — مرفوض |

## 3. مخاطر مراجعة الكود الجديد (قائمة للمراجع المستقل)

1. `stringResource` داخل `maxGovernanceLadder.map { … }` — نمط موجود في الشجرة (`AudioBackendSection` …)، لكنه يحتاج مُصرّفًا للتأكيد.
2. `MaxCardShell(onClick = onOpenDetails)` — عند `null` لا قابلية نقر ولا دور `Button`؛ عند غير `null` القشرة كلها هدف ٤٨dp+.
3. `R.string.max_gov_*` — ١٥ مفتاحًا في `values/` و`values-ar/` فقط؛ بقية الـ٨٢ لغة ستنقصها المفاتيح (سياسة §٠.٢: لا تعبئة إلا بأمر «زامن»).
4. `MaxOwnerBadge` يستعمل `semantics { contentDescription = … }` — لم يُختبر مع TalkBack.
5. الاختبار الجديد يفترض `ControlOwnership.Owner.priority` ثابتًا؛ إن غُيّر السلّم لاحقًا يجب تحديث الترتيب في `MaxGovernance.kt` (والاختبار سيسقط ليُنبِّه).

## 6. ما يجعل الجولة «مكتملة» بمعنى الطلب §٢

| شرط النجاح | الحالة |
| --- | --- |
| الشاشة الأولى تصف وضع الجهاز | **جزئي** — تصفه فعلًا، وينقصها «من يحكم» (سلّم في التحكّم فقط) |
| الوظيفة من مكانها الطبيعي أو بأمر | **جزئي** — الاسم يعمل، القصد لا |
| الفعل ونتيجته في إطار واحد | **لا** — لم يُبنَ |
| نمط واحد لكل تفاعل | **جزئي** — الحكّام وُحّدوا، والثقة لا |
| المبتدئ/الخبير | **غير مقيس** |
| «من يحكم» ظاهر قبل التعديل | **نعم** في التحكّم، لا في «الآن» |
| مسارات الكتابة لم تتغيّر | **نعم** (قراءة كود) |
| المداخل القديمة لم تنكسر | **نعم** (لا مسار تغيّر؛ لم تُختبر على جهاز) |
| الواجهة أخف أو مساوية | **غير مقيس** — لا إضافة قراءة/رسم متكرّر، لكن لا قياس |

⇒ لا يُقال «اكتملت إعادة الهندسة». الجولة سلّمت: الجرد، التشخيص، البنية، النظام، شريحة الحكّام، وحدودها.
