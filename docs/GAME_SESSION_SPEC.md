# GAME_SESSION_SPEC — آلة حالة الجلسة

> مخرج المرحلة 4. الجلسة هي العقد الذي يجعل الوحدات منظومة: بلا «لعبة تعمل الآن» لا معنى للتراكب ولا
> للوحة الأداء. كل مصدر حقيقة هنا **مقيس في الأصل**؛ وكل رقم زمني **اختيار تصميمي** مكتوب أنه اختيار.

---

## 1. ما يملك الجلسة

| البند | القرار | الدليل |
| --- | --- | --- |
| المالك | `gamespace` وحده | الأصل الأكبر (66 مكوّنًا) وفيه `GameEventService` + `GameEventService$GameBroadcastService` |
| المستهلكون | `gameassist` · `floatwindow` · `helperline` · `gamepad` · `highlights` · `notes` · `widget` · `gamepi` | كلها تعمل «أثناء اللعب» فقط، بمكوّناتها المقيسة |
| النقل | `bindService` على عقد `ISessionService` + بثّ تغيير محمي بصلاحية توقيع | نمط الأصل: فعل `ACTION_GAME_ASSIST_SERVICE` + صلاحية `signature` |

**قاعدة واحدة لا تُخترق:** لا وحدة تُقرّر بنفسها «هذه لعبة تعمل». تُسأل المالك، وإن لم يجب فالحالة
`UNKNOWN` (لا تخمين من `UsageStats` محليًّا في كل وحدة — ينتج نزاعات ويستهلك بطارية).

---

## 2. الحالات

| الحالة | معناها | من يراها |
| --- | --- | --- |
| `IDLE` | لا لعبة، لا تراكب، لا خدمة تعمل | الجميع |
| `ARMED` | لعبة في المقدمة، لكن التراكب غير معروض بعد | `gameassist` يجهّز النافذة فقط |
| `ACTIVE` | لعبة في المقدمة + التراكب معروض + الجلسة تُحصي | كل المستهلكين |
| `PAUSED` | اللعبة موجودة لكن ليست في المقدمة (مكالمة، إشعار، شاشة قفل) | التراكب مخفي، الحالة محفوظة |
| `ENDED` | خرجت اللعبة أو أُوقفت الجلسة يدويًّا | تنظيف كامل |

`ARMED` موجودة لأن قياس الأصل يفصل **الاستعداد** (`GameAssistService` يُربط ويُجهَّز) عن
**العرض** (`ACTION_SHOW_PANEL`/`ACTION_HIDE_PANEL` في `GameCardAssist`) — فلا نبني نافذة قبل الطلب.

---

## 3. الانتقالات

| من | إلى | الشرط | من ينفّذ |
| --- | --- | --- | --- |
| `IDLE` | `ARMED` | مقدمة الشاشة = حزمة في قائمة الألعاب | `gamespace` |
| `ARMED` | `ACTIVE` | طلب عرض (زر/إيماءة/إعداد «تلقائي») + إذن التراكب ممنوح | `gameassist` |
| `ACTIVE` | `PAUSED` | فقدان المقدمة (مكالمة/قفل/إشعار ملء الشاشة) | `gamespace` |
| `PAUSED` | `ACTIVE` | عودة المقدمة خلال مهلة السماح | `gamespace` |
| `PAUSED` | `ENDED` | انتهاء مهلة السماح أو إغلاق اللعبة | `gamespace` |
| `ARMED`/`ACTIVE` | `ENDED` | خروج اللعبة/إيقاف يدوي | `gamespace` |

**المهل (اختيار تصميمي، لا قياس):** `ACTIVE→PAUSED` فوري عند فقدان المقدمة (لا تأخير: التراكب فوق
مكالمة عيب) · `PAUSED→ENDED` بعد **60 ثانية** · إعداد المستخدم يعدّلها. والسبب: فقدان المقدمة ثانية
لا يعني انتهاء اللعبة (نافذة نظام)، والانتظار الطويل يُبقي خدمات تعمل بلا فائدة.

## 4. مصادر الحقيقة والكشف

| المصدر | الاستخدام | حالته عندنا |
| --- | --- | --- |
| قائمة الألعاب المملوكة | «هل هذه الحزمة لعبة؟» | تُبنى من `LaunchableActivity` + إدخال المستخدم، **لا** من قائمة Nubia المضمّنة (غير مقروءة) |
| `UsageStatsManager`/`ActivityManager` | الحزمة في المقدمة | مقيس في MaxManager كمرجع معرفي؛ يُقاس هنا في المرحلة 5 |
| بثّ النظام (`SCREEN_OFF`/`ON`، `USER_PRESENT`) | `PAUSED` عند القفل | معياري |
| عقد الجلسة نفسه | كل المستهلكين | يُختبر بوحدة الاختبار |

**لا يُستخدم:** `AccessibilityService` لجلب المقدمة (سطح حساس يحتاج إقرارًا صريحًا من المستخدم
وصلاحية واسعة) — يُترك `UNSUPPORTED` بدلًا من طلبه لأغراض داخلية.

## 5. العقد (Interface)

```kotlin
interface ISessionService {
    fun session(): SessionSnapshot          // حالة + حزمة + وقت البدء + إصدار العقد
    fun observe(cb: ISessionObserver)        // تغييرات مدفوعة، لا استعلام دوري
}

data class SessionSnapshot(
    val state: SessionState,   // IDLE | ARMED | ACTIVE | PAUSED | ENDED
    val packageName: String?,  // حزمة اللعبة حين توجد
    val since: Instant,
    val contractVersion: Int,  // يرفض المستهلك عقدًا لا يفهمه
)
```

**قواعد النقل:**
- `bindService` صريح + صلاحية `dev.redlab.gamespace.permission.SESSION`.
- `contractVersion` لا يُتجاهل: مستهلك بنسخة أقل **يُعطّل** الميزة ويُعلن `UNSUPPORTED`، لا «يجرّب».
- البثّ محمي بصلاحية توقيع، ولا يحمل بيانات حساسة (حزمة اللعبة فقط).

## 6. سلوك الحافّات (Edge cases)

| الحالة | السلوك |
| --- | --- |
| لعبة أُغلقت بقوة (force stop) | `ENDED` عند أول استعلام؛ التنظيف فوري، بلا اعتماد على `onDestroy` |
| إعادة تشغيل الجهاز | لا استعادة تلقائية لجلسة؛ تبدأ من `IDLE` |
| اللعبة في وضع ملء الشاشة عبر `Presentation` (تعدّد شاشات) | الجلسة تبقى `ACTIVE`، والتراكب يتبع الشاشة المقيسة (`OVERLAY_SPEC.md` §5) |
| تغيير الحزمة بسرعة (تبديل مهام) | debounce **قصير (اختيار: 300ms)** لمنع وميض التراكب |
| عدم وجود إذن التراكب | `ARMED` تبقى، والعرض يفشل بـ`NEEDS_PERMISSION` معلنة |
| وحدة مستهلكة غير مثبَّتة | لا أثر على الجلسة؛ لا خطأ |

---

## 7. اختبار القبول (المرحلة 6)

1. فتح لعبة من `gamespace` ⇒ لقطة الجلسة تصل `ACTIVE` على **جهاز حقيقي**.
2. مكالمة واردة ⇒ `PAUSED` والتراكب مخفي (لا فوق شاشة المكالمة).
3. عودة ⇒ `ACTIVE` بموضع تراكب محفوظ.
4. خروج ⇒ `ENDED` وصفر خدمات تعمل (`dumpsys activity services` بلا عملياتنا).

> ما لم يُقَس بعد: البند 1–4 كلها **تحتاج جهازًا**؛ وهذا الملف مواصفة، لا دليل نجاح.
